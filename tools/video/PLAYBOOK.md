# נוהל יומי: סרטוני פתרון לבחינות בגרות

המטרה: בכל הרצה מכינים **מועד שלם**: את כל הבחינות שעדיין `todo` במועד הבא בתור (`tools/video/queue.json`), כלומר כל השאלונים של אותו מועד (35371, 35372, 35471, 35472, 35571, 35572).
לכל שאלה בבחינה מכינים סרטון פתרון עם קריינות ופתרון כתוב, ומעלים לאתר.
הסדר: קיץ מועד ב ← קיץ מועד א ← חורף, משנה לשנה אחורה. המפתח `<שאלון>_<שנה>_<חודש>`: חודש 8 = קיץ ב, 6 = קיץ א, 1 = חורף.

אוראל לא מאשר לפני ההעלאה. לכן כל תשובה חייבת להיבדק מול המפתח הרשמי של משרד החינוך.
לא שואלים שאלות. אם בחינה תקועה, מסמנים אותה `needs-review` עם הערה (`"note"`) ועוברים לבאה באותו מועד.

## 0. הכנה
```bash
cd ~ && git clone --depth 1 https://github.com/orelpinchasi/pshut-math && cd pshut-math
which pdftotext pdftoppm ffmpeg google-chrome; python3 -c "import playwright"
```
מוצאים ב-`queue.json` את הרשומה הראשונה עם `"status":"todo"`, לוקחים את המועד שלה (השנה והחודש), ועובדים על **כל** הרשומות `todo` עם אותה שנה ואותו חודש. כדאי לעשות commit, push ועדכון התור אחרי כל בחינה, כדי שעבודה שהושלמה לא תלך לאיבוד אם ההרצה תיעצר.
הקישורים לטופס (`pdf`) ולתשובות (`sol`) נמצאים ב-`bagrut-data.json` לפי המפתח `k`, למשל `35371_2026_8`.

## 1. קריאת הבחינה
```bash
mkdir -p /tmp/bag/K && cd /tmp/bag/K
curl -sS -o q.pdf "<pdf>"; curl -sS -o s.pdf "<sol>"
pdftotext -layout q.pdf q.txt; pdftotext -layout s.pdf s.txt
pdftoppm -r 55 -png q.pdf pg      # כדי לראות שרטוטים וגרפים
```
- בקובץ התשובות יש כמה גרסאות (א/ב/ג) עם מספרים שונים. מזהים איזו גרסה תואמת לטופס שפורסם (בודקים נתון מספרי מהטופס), ועובדים רק לפיה.
- סימני שורש ושברים נעלמים לפעמים מהטקסט. כשמשהו לא ברור, מסתכלים בתמונת העמוד.

## 2. פתרון ובדיקה
- פותרים כל שאלה במלואה ובודקים **כל** תשובה סופית מול הגרסה הנכונה במפתח.
- אם התשובה לא תואמת, מחפשים את הטעות. לא מפרסמים תשובה שסותרת את המפתח.
- סעיף שמבקש סקיצה או בחירת גרף: מתארים לפי מה שרואים בתמונת העמוד.

## 3. כתיבת התסריטים
יוצרים `tools/video/exams/K/q1.py` … `qN.py`, שאלה לכל קובץ, לפי הדוגמאות ב-`exams/35471_2026_6/` (הכי עדכניות).
כל קובץ מתחיל ב:
```python
from common import *
setx(35371,2026,8);PG=<מספר העמוד של השאלה בטופס>
QH=QH(1)
```
מבנה קבוע (`SC`):
1. `intro(...)`: כרטיס פתיחה קצר ("היי! שאלה X: <נושא>. בוא נתחיל.").
2. סצנת נתונים: הכותרת "מציבים את הנתונים" או "מסדרים את הנתונים", והשורה הראשונה `("rule","התשובות נמצאות בנתונים", ...)`.
3. סצנה לכל סעיף, עם כותרת שמתחילה ב-`"סעיף א · ..."`. תשובות סופיות בשורות `"box"`.
4. "מה למדנו?": שתי שורות של לקח, ובסוף `("rule","פשוט ליהנות", ...)`.
5. `OUT`.

סגנון הקריינות, השדה השלישי בכל שורה: זה הקול של אוראל.
- עברית מדוברת, משפטים קצרים. **כל מספר וכל סימן נכתב במילים** ("שלושים ושתיים נקודה שש", "איקס בריבוע", "איי בי"), כי מנוע הקול מקריא את המילים כמו שהן.
- ביטויים קבועים: "בוא נראה מה הם רוצים", "מהמם", "כל הכבוד!", "רגע, רגע, רגע", "אין שאלה" (כשהתשובה כבר מחכה בנתונים או בסעיף קודם).
- לא מציגים קודם את תקציר הנושא ולא את רשימת הכללים. הכללים משתלבים תוך כדי הפתרון.
- חלונית השאלה (`Q`) היא **ניסוח מקוצר במילים שלנו**. לא מעתיקים את נוסח הבחינה. `hl` מסמן את השורות הפעילות, `done` את הסעיפים שכבר נפתרו.
- נוסחאות על הלוח עטופות ב-`M(...)`. לא שמים עברית בתוך `M`. לא שמים סימן מתמטי צמוד למילה עברית מחוץ ל-`M`.
- שרטוט (`fig`): `bell` (פעמון), `tree` (עץ, עם `c1`/`c2` לכותרות השלבים), `plot` (גרפים, נקודות, קטעים, מעגלים, מצולעים; `eq:True` לגאומטריה; `axes:False` לשרטוט בלי צירים). הדוגמאות בתיקיות הבחינות.

## 4. רינדור ובדיקה
מתוך `tools/video/exams/K`:
```bash

```
מסתכלים על התמונות העמוסות (הסצנה האחרונה של כל סעיף עם שרטוט), למשל בגיליון של 4 תמונות.
מתקנים חפיפות של תוויות, טקסט חתוך וכיוון כתיבה שבור.
```bash
mkdir -p out; for i in $(seq 1 N); do python3 ../../build.py q$i out/K_$i.mp4; done

# מרנדרים שוב את השאלות שמופיעות ב-CHANGED
```
